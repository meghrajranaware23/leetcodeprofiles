# 📝 MST (Kruskal's/Prim's)

> **Day 21** · Minimum Spanning Tree · ★★★★☆ · 25 XP · 15 min read

---

Connect all nodes at **minimum total edge cost** — that's a Minimum Spanning Tree. Today: **Kruskal's** — sort edges by weight, greedily add each edge if it connects two different components (Union-Find checks). Second quest uses UF differently: group indices by swap pairs, sort characters within each component.

> **Preview contrast (Dijkstra vs MST):** Dijkstra = shortest path **from one source**. MST = minimum cost to **connect all nodes** — no fixed start; Kruskal picks cheapest safe edges globally.

---

## Part 1 — Learn the Pattern

### 1. What is the pattern?

**Kruskal's MST:**
1. Sort all edges by weight ascending
2. Initialize UF with n separate sets
3. For each edge `(u, v, w)` in sorted order:
   - If `find(u) != find(v)`: `union(u, v)`, add `w` to answer
   - Else: skip (would create cycle)
4. Stop when you've added `n-1` edges (or heap variant in Prim's style)

**UF for component grouping (#1202):** Union swap pairs → bucket indices by root → sort chars descending per bucket → rebuild string left-to-right.

### 2. Simple explanation

You're wiring a village with the cheapest cable plan. Sort every possible cable by price. Buy the cheapest first — but skip any cable that connects two houses already on the same network (cycle). UF tells you instantly if two houses share a network. After n−1 cables, everyone is connected at minimum total cost.

For Smallest String With Swaps: indices that can swap are connected components. Within each component, you can rearrange characters freely — so place the smallest possible letters at those indices by sorting chars in each UF group.

### 3. Visual — Kruskal step by step

```
Points 0,1,2 with edge costs:
  0—1: 1    1—2: 2    0—2: 4

Sorted: (0,1,1), (1,2,2), (0,2,4)

Add 0—1 (cost 1): UF {0,1} | {2}
Add 1—2 (cost 2): UF {0,1,2}  ← 2 edges, all connected
Skip 0—2 (cost 4): find(0)==find(2) → cycle

MST cost = 3
```

### 4. Visual — UF component char sort

```
s = "dcab", pairs = [[0,3],[1,2],[0,2]]

Union pairs → component {0,1,2,3} all connected
Chars at indices: d(0), c(1), a(2), b(3)
Sorted descending bucket: a,b,c,d
Assign back index order: a,b,c,d → "abcd"
```

### 5. The universal template

**Kruskal:**
```
sort edges by weight
UF init(n); cost = 0; edges_used = 0
for (u, v, w) in edges:
    if find(u) != find(v):
        union(u, v)
        cost += w
        edges_used++
        if edges_used == n - 1: break
return cost
```

**Component sort (swaps):**
```
for (a, b) in pairs: union(a, b)
for i in 0..n-1: buckets[find(i)].add(s[i])
sort each bucket descending
for i in 0..n-1: res[i] = buckets[find(i)].pop()
```

### 6. Why brute force fails

| Brute force | Problem |
|---|---|
| Try all subsets of edges | Exponential |
| Dijkstra from one node | Doesn't connect all nodes at min cost |
| Greedy without cycle check | May form cycles — UF prevents this |
| Prim/Kruskal without sorting | Misses cheaper edges |
| BFS for MST | Wrong tool entirely |

**The insight:** Global cheapest edge that doesn't cycle — sort + UF is the proof-backed greedy.

### 7. Kruskal vs Prim vs Dijkstra

| | **Kruskal** | **Prim** | **Dijkstra** |
|---|---|---|---|
| Goal | MST — connect all | MST — connect all | Shortest from source |
| Structure | Sort edges + UF | Heap grows tree from seed | Heap from source |
| Best when | Sparse edge list | Dense graph | Single-source path |
| Today's quest | Connect Points (Prim-style heap+UF) | Alternate | Not MST |

Connect Points uses a **Prim-style** heap with UF skip — same MST spirit, different edge generation (all pair distances).

### 8. Pattern signals & recognition clues

| When the problem says… | Think… |
|---|---|
| "min cost to connect all points/nodes" | MST — Kruskal or Prim |
| "Manhattan distance between all pairs" | Generate edges + MST |
| "smallest string with swaps" | UF components + sort chars |
| "shortest path from A to B" | Dijkstra — not MST |
| "redundant edge in tree" | UF cycle detect (Day 17) |

**Keywords:** `sort edges` · `Kruskal` · `union if different root` · `n-1 edges` · `component sort`

### 9. Common beginner mistakes

| Mistake | Fix |
|---|---|
| Adding edge without UF check | Creates cycles — must verify different roots |
| Forgetting n−1 edges for full MST | n nodes need exactly n−1 MST edges |
| Using MST for single-pair shortest path | Dijkstra instead |
| Sort ascending vs descending | Edge weights ascending; **chars descending** for smallest string |
| Not unioning all pairs in swap list | Every pair in `pairs` must be united |
