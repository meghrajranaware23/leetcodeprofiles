# 📎 Appendix A: Complete Pattern Cheat Sheet

> Every pattern from all 30 days. One-line descriptions. When to use. Complexity at a glance.

---

## E-Rank Patterns (Foundation)

| # | Pattern | One-Line Description | When to Use | Time | Space |
|---|---------|---------------------|-------------|------|-------|
| 1 | **Linear Traversal** | Walk through every element once, applying logic per element. | Any problem requiring you to inspect or transform all elements. | O(n) | O(1) |
| 2 | **Reverse Traversal** | Iterate from the end to the beginning of an array/string. | Building results right-to-left, suffix-based logic, stack-like processing. | O(n) | O(1) |
| 3 | **String Building** | Construct strings character by character using efficient structures. | String concatenation, transformation, or building results char-by-char. | O(n) | O(n) |
| 4 | **Frequency Map** | Count occurrences of each element using a hash map. | Anagram detection, duplicate checking, "most/least frequent" queries. | O(n) | O(k) |
| 5 | **Hash Map Lookup (Two Sum)** | Store complements in a map; look up as you iterate. | Pair-finding problems: "find two elements that satisfy X." | O(n) | O(n) |
| 6 | **Sort-First** | Sort the array as a preprocessing step to simplify the problem. | Problems where relative order doesn't matter and sorting reveals structure. | O(n log n) | O(1)–O(n) |

## D-Rank Patterns (Pointers)

| # | Pattern | One-Line Description | When to Use | Time | Space |
|---|---------|---------------------|-------------|------|-------|
| 7 | **Two Pointers (Converging)** | Left and right pointers move toward each other on sorted data. | Pair sum on sorted array, container with most water, palindrome check. | O(n) | O(1) |
| 8 | **Two Pointers (Read/Write)** | Read pointer scans; write pointer tracks valid output position. | Remove duplicates, remove element, compact arrays in-place. | O(n) | O(1) |
| 9 | **Fast & Slow Pointers** | Two pointers at different speeds to detect cycles or find midpoints. | Cycle detection in sequences, finding middle elements, duplicate detection. | O(n) | O(1) |
| 10 | **Three/Multi-Pointer** | Extension of two pointers with three or more simultaneous pointers. | 3Sum, 4Sum, Dutch National Flag, multi-way partitioning. | O(n²) | O(1) |
| 11 | **In-Place Reversal** | Reverse a segment of the array using swap operations. | Rotate array, reverse words, palindrome construction. | O(n) | O(1) |

## C-Rank Patterns (Windows & Sums)

| # | Pattern | One-Line Description | When to Use | Time | Space |
|---|---------|---------------------|-------------|------|-------|
| 12 | **Fixed Sliding Window** | Maintain a window of exactly size k, sliding one position at a time. | Max/min/sum/average of every k-length subarray. | O(n) | O(1) |
| 13 | **Variable Sliding Window** | Expand window right, shrink from left when constraint violated. | Smallest/longest subarray/substring meeting a condition. | O(n) | O(1) |
| 14 | **Sliding Window + Hash Map** | Variable window with a frequency map tracking window contents. | Substring with at most k distinct chars, anagram search, permutation in string. | O(n) | O(k) |
| 15 | **Prefix Sum** | Precompute cumulative sums; answer range queries in O(1). | Range sum queries, subarray sum equals k, count subarrays with sum. | O(n) | O(n) |
| 16 | **Prefix Sum + Hash Map** | Combine prefix sums with a hash map to find subarrays summing to target. | Subarray sum equals K, contiguous array, count of range sums. | O(n) | O(n) |
| 17 | **Difference Array** | Mark range start/end with +val/−val; take prefix sum to reconstruct. | Bulk range update queries, flight bookings, car pooling. | O(n + q) | O(n) |
| 18 | **Kadane's Algorithm** | Track running max subarray sum, resetting when sum goes negative. | Maximum subarray, maximum product subarray, circular subarray. | O(n) | O(1) |

## B-Rank Patterns (Advanced Structures)

| # | Pattern | One-Line Description | When to Use | Time | Space |
|---|---------|---------------------|-------------|------|-------|
| 19 | **Monotonic Stack (Increasing)** | Maintain a stack of increasing values; pop when a larger element arrives. | Next greater element, daily temperatures, stock span. | O(n) | O(n) |
| 20 | **Monotonic Stack (Decreasing)** | Maintain a stack of decreasing values; pop when a smaller element arrives. | Next smaller element, largest rectangle in histogram. | O(n) | O(n) |
| 21 | **Histogram / Trap Stack** | Use monotonic stack to compute area or trapped volume between bars. | Largest rectangle in histogram, trapping rain water. | O(n) | O(n) |
| 22 | **Spiral Traversal** | Walk the boundary of a matrix, shrinking bounds after each loop. | Spiral matrix, spiral matrix II, rotate image. | O(m×n) | O(1) |
| 23 | **Diagonal Traversal** | Traverse matrix along diagonals using `i + j = constant` grouping. | Diagonal traverse, anti-diagonal grouping, zigzag level order. | O(m×n) | O(min(m,n)) |
| 24 | **2D Prefix Sum** | Extend prefix sums to 2D with inclusion-exclusion for rectangle queries. | Submatrix sum queries, count submatrices with target sum. | O(m×n) | O(m×n) |
| 25 | **Hash Key Design** | Design custom hash keys to group or identify equivalent elements. | Group anagrams (sorted key), encode/decode strings, isomorphic strings. | O(n×k) | O(n×k) |
| 26 | **Interval Merge** | Sort intervals by start, merge overlapping ones by comparing end times. | Merge intervals, insert interval, meeting rooms, non-overlapping intervals. | O(n log n) | O(n) |
| 27 | **Sweep Line** | Process events (start/end) on a timeline to track active count. | Meeting rooms II, max concurrent events, my calendar. | O(n log n) | O(n) |

## A-Rank Patterns (Elite Techniques)

| # | Pattern | One-Line Description | When to Use | Time | Space |

| 33 | **XOR Tricks** | Use XOR properties (self-inverse, commutative) for cancellation. | Single number, find missing number, find two unique numbers. | O(n) | O(1) |

# 📎 Appendix B: Complexity Reference Table

> Big-O reference for all major array and string operations across languages.

## Fundamental Array Operations

| Operation | Array (C++) | List (Python) | ArrayList (Java) | Notes |
|-----------|-------------|---------------|-------------------|-------|
| Access by index | O(1) | O(1) | O(1) | Direct memory offset |
| Search (unsorted) | O(n) | O(n) | O(n) | Linear scan |
| Search (sorted) | O(log n) | O(log n) | O(log n) | Binary search |
| Insert at end | O(1)* | O(1)* | O(1)* | Amortized; resize may be O(n) |
| Insert at index | O(n) | O(n) | O(n) | Shift elements right |
| Delete at end | O(1) | O(1) | O(1) | No shifting needed |
| Delete at index | O(n) | O(n) | O(n) | Shift elements left |
| Sort | O(n log n) | O(n log n) | O(n log n) | Introsort / Timsort |
| Reverse | O(n) | O(n) | O(n) | In-place swap |
| Copy | O(n) | O(n) | O(n) | Element-by-element |

## Fundamental String Operations

### Practical Constraints (Interview Rule of Thumb)

| n (input size) | Target Complexity | Why |
|---------------|------------------|-----|
| n ≤ 10 | O(n!) or O(2^n) | Brute force / backtracking is fine |
| n ≤ 20 | O(2^n) | Bitmask DP, full subset enumeration |
| n ≤ 500 | O(n³) | Triple nested loops acceptable |
| n ≤ 5,000 | O(n²) | Double nested loops acceptable |
| n ≤ 10⁶ | O(n log n) | Sort + scan, merge sort, priority queue |
| n ≤ 10⁷ | O(n) | Single pass, two pointers, sliding window |
| n ≤ 10⁸+ | O(log n) or O(1) | Binary search, math, formula |

> **Rule of thumb:** Most online judges run ~10⁸ simple operations per second. If your algorithm does more than ~10⁸ operations for the given input size, it will TLE (Time Limit Exceeded).
