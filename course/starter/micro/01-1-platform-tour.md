## Part 1 — Platform Setup & Daily Workflow

### 1. Why today is different

Day 1 is not about algorithms. Most beginners open LeetCode, pick a random Easy, stare at a blank editor, and quit. You're building a **home base** first — account, editor, habit slot, and one Accepted submission. Momentum beats difficulty today.

### 2. The skill in one sentence

> **Platform Setup & Daily Workflow** — configure LeetCode once, then repeat the same daily loop every day.

### 3. Your daily workflow loop

Every Starter Path day follows this loop. Memorize it now:

```
┌─────────────────────────────────────────────────────────┐
│  READ  →  TRY (5 min)  →  LEARN  →  REFLECT  →  REPEAT │
└─────────────────────────────────────────────────────────┘
     ↑                                              │
     └──────────── same time tomorrow ──────────────┘
```

| Step | What you do | Where on LeetCode |
|------|-------------|-------------------|
| **Read** | Title, constraints, examples — no editor | Problem page |
| **Try** | Paper plan + 5-minute attempt | Your editor |
| **Learn** | Hints → walkthrough → solution study | This course + Discuss |
| **Reflect** | Checkpoint + habit + one journal line | Your mistake journal |

### 4. Platform map (know these areas)

```
LeetCode Home
├── Problem Set ────── filter Easy · sort by acceptance
├── Editor ─────────── language, Run vs Submit
├── Submissions ────── your AC history (revisit weekly)
└── Discuss/Editorial ─ AFTER your attempt only
```

| Area | What to do today |
|------|------------------|
| **Problem Set** | Filter to Easy · bookmark the list |
| **Editor** | Pick C++, Python, or Java in Profile → Settings |
| **Run / Submit** | Run = your tests · Submit = full judge |
| **Submissions** | Find your first AC after FizzBuzz |
| **Discuss / Editorial** | Do not open until after your attempt |

### 5. What strong beginners do on Day 1

| Weak habit | Strong habit |
|---|---|
| Random Hard problem as "motivation" | One Easy warmup with full submit flow |
| Skip account setup, code as guest | Language set, journal created, calendar blocked |
| Treat Run and Submit as the same | Run on Example 1 first, Submit when confident |
| No daily time slot | Same 20-minute block every day |
| Open Discuss before trying | Attempt → then learn from walkthrough |

### 6. The key insight

> **One Accepted submission changes how LeetCode feels.** Today you prove the platform works for you — not that you're already fast.

### 7. Common Day 1 mistakes

| Mistake | Fix |
|---|---|
| Picking a hard "challenge" problem | FizzBuzz exists to teach submit flow, not cleverness |
| Skipping the setup checklist | 5 minutes of setup saves confusion every future day |
| Not blocking calendar time | If it's not scheduled, it won't happen |
| Reading editorials before trying | You lose the "attempt first" habit on day one |
| No mistake journal | Create it now — one line per day is enough |
