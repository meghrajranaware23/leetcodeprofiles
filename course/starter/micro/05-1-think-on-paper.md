## Part 1 — Brute Force Thinking & 5-Minute Rule

### 1. Why paper comes before code

Most Wrong Answers on Easy problems come from misreading or skipping the plan — not from missing a clever algorithm. Three lines on paper cost 90 seconds and save 20 minutes of random edits.

### 2. The skill in one sentence

> **No editor until paper has 3 lines of plan OR the 5-minute timer expires.**

### 3. 5-Minute Paper Timer Workflow

```
START TIMER (5:00)
  ├─ 0:00–1:30  Read (4-part framework)
  ├─ 1:30–3:30  Brute force in plain English on paper
  ├─ 3:30–5:00  Attempt code OR log stuck point
STOP → hints allowed
```

### 4. Brute force before optimize

| Problem | Brute force (valid today) | Optimize later |
|---------|---------------------------|----------------|
| Good Pairs | Double loop all pairs | Frequency count |
| Contains Duplicate | Compare all pairs | Hash set |

> Accept brute force if it passes constraints. Optimization is a **second pass**, not Day 5's goal.

### 5. What strong beginners do

| Weak habit | Strong habit |
|---|---|
| Open editor while still reading | Timer starts after 4-part read |
| Skip brute force — hunt for optimal | Write O(n²) plan first if it fits constraints |
| Give up at 2 min without logging | Log stuck point at 5 min — then hints |
| Treat Phase 1 proof as "extra" | Block 10 min for test-1 after today's quests |

### 6. The key insight

> **Brute force you understand beats optimal code you copied.** Day 5 proves you can plan — not that you're already fast.

### 7. Common Day 5 mistakes

| Mistake | Fix |
|---|---|
| Opened editor before paper plan | Timer + 3-line plan before first keystroke |
| Skipped brute force — jumped to hash set | Double loop is valid today if constraints allow |
| Gave up at 2 minutes | Log stuck point at 5 min, then hints |
| Rushed Phase 1 proof without synthesis | test-1 Valid Palindrome = Days 2–4 combined |
