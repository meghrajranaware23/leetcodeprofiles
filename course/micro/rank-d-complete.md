## 🧠 Your Pattern Recognition Cheat Sheet

When a new problem appears, scan for these signals:

| If the problem says... | Reach for... |
|---|---|
| "sorted" + "pair" / "two sum" / "closest sum" | Opposite-end two pointers |
| "three numbers" / "triplet" / "k-sum" | Sort + fix-one + two pointers |
| "cycle" / "duplicate" / "middle" / "linked list" | Fast & slow pointers |
| "subarray of size k" / "permutation in string" | Fixed-size sliding window |
| "longest substring" / "minimum window" / "at most k" | Variable-size sliding window |
| "in-place" + "remove" / "compact" | Read-write pointer (E-Rank, still applies) |

> 💡 **The D-Rank skill:** Pointers eliminate inner loops. Before you write nested `for` loops on sorted or contiguous data, ask: *can one pointer track the left boundary while another tracks the right?*

## 🎯 How to Approach Unseen Problems

You've trained on 10 quests and 3 test problems. Real LeetCode won't label the pattern for you. Use this four-step loop on every new problem:

1. **Read for constraints, not details.** Sorted? Fixed window size? At most two per group? These narrow the pointer family before you code.
2. **Scan the signal table.** Match keywords to your cheat sheet above. Say the pattern name out loud: *"permutation in string → fixed window + frequency."*
3. **Reject brute force in your head.** If your first instinct is nested loops, ask whether sorting + two pointers or a sliding window eliminates the inner loop.
4. **Check the skeleton, not the solution.** You need the structure: sort + left/right convergence, fix-one outer loop, window expand/shrink with a running counter.
