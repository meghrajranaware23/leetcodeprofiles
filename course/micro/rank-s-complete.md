### S-Rank Synthesis — Combination Recognition (Days 28–30)

Hard problems rarely announce one pattern. They **layer** them. When you see these compound signals, name both techniques before you code:

| If the problem says... | Stack these patterns... |
|---|---|
| "sliding window max/min" / "max in every window of size k" | Variable/fixed window **+** monotonic deque |
| "shortest subarray sum ≥ k" **with negatives allowed** | Prefix sum **+** monotonic deque (not Kadane's) |
| "longest repeating character" / "at most k replacements" | Variable window **+** frequency budget (max char count trick) |
| "count unique characters in all substrings" / "distinct chars across all subarrays" | Contribution counting on strings (each char's span × positions) |
| "algebraic equation with \|xi − xj\|" / "minimize max distance in window" | Rewrite the math, then window **+** monotonic max/min deque |

> 💡 **The Legend skill:** Your cheat sheet is no longer a checklist — it's a **decision tree**. Read the problem once. Name the primary pattern. Ask what *second* structure the constraint demands inside it. If the window needs O(1) min/max → deque. If the sum constraint breaks with negatives → prefix + deque, not Kadane's. If the answer counts over all substrings → contribution, not brute enumeration.

## 🎯 How to Approach Unseen Problems

You've trained across **52+ quests**, **18 rank tests**, and **3 synthesis days**. Real contests and LeetCode Hard problems won't label anything for you. At Legend level, use this four-step loop:

1. **Read for the constraint stack, not the story.** Ignore the narrative framing. Ask: *What must stay true?* In-place? Negative numbers? Multiple simultaneous counters? A deque inside the window? These reveal the **pattern family chain** before you touch an editor.
2. **Walk the decision tree top-down.** Start with E/D signals (pointer? window? prefix?). Escalate to C/B if state or structure is needed (freq map, stack, 2D prefix). Reach for A-Rank only when strings demand hash rolls, LPS, or bitmasks. If two families fit, you're in S-Rank territory — **name both patterns out loud**.
3. **Reject the first instinct if it's brute force.** Legend hunters don't enumerate subarrays or simulate strings. If your gut says nested loops, pause: *Can I sort first? Can I maintain a deque? Can I count contributions instead of iterating?* The simpler single-pattern solution always wins when it fits.
4. **Sketch the skeleton chain, not the full solution.** You need the structure of each layer: window expand/shrink + deque push/pop, prefix array + monotone queue of indices, contribution formula `(i - prev)(n - j)`, rolling hash with prime mod. Fill in details after the architecture is locked.

If you can name the pattern stack in under 30 seconds, you've already won half the battle. The code is just filling in the templates you've drilled for thirty days.
